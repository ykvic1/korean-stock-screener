# 기업행위 공시 접수번호 대조의 연속 처리

2026-11-05 기준으로 과거 공시 후보 정리는 119개 인접 월 구간까지 준비돼 있다.
기존 공식 JSON 대조기는 1회에 후보 2건·실제 조회 시도 6회로 제한되어 있어,
이 단위는 유지하면서 검증된 체크포인트를 따라 여러 묶음을 연속 처리한다.

- 1회 최대 256묶음·후보 512건·공식 조회 시도 1,536회·55분이다.
  실패한 조회 시도도 포함하며, 두 후보·최대 6회 조회마다 검증 후 저장한다.
- UTC 02:55·06:55·10:55·14:55·18:55·22:55(한국 11:55·15:55·19:55·23:55·03:55·07:55)에
  하루 6회 실행한다. 예약분 상한은 후보 3,072건·조회 시도 9,216회다.
  기존 하루 2회·64묶음 대비 설정상 처리 상한은 12배다. 기존 소규모 대조기는 유지한다.
  수동·병합 시 최초 실행과 다른 수집기의 사용량은 이 예약분 상한에 포함되지 않는다.
  공유 키의 실제 제공자 인증·쿼터 오류에서는 중단하며 한도 우회나 오류 재시도는 하지 않는다.
- 기존 2~3주는 종전 실행 주기 기준 추정이며 필수 대기 기간이 아니다.
  동일한 후보 수와 묶음 처리속도라면 상한 변경 효과는 크지만, 실제 기간은
  후보 밀도·55분 제한·비공개 저장소 쿼터·다른 수집기의 사용량에 따라 달라진다.
  월 구간 수는 작업량이 균등하지 않으므로 7/119만으로 날짜를 확정하지 않는다.
- 수동 실행은 기본 시험 모드다. `feat(v3.0b): structured action continuation`으로
  시작하는 main 병합 커밋은 승인된 이번 개발의 최초 연속 실행을 시작한다.
  `feat(v3.0b): accelerate structured action` 병합도 가속 설정으로 즉시 시작한다.
- 기존 공식 대조기와 같은 쓰기 대기열을 사용한다. 보고서·큐·체크포인트의
  바이트와 해시를 확인하고, 다른 실행이 바꾼 커서는 덮어쓰지 않는다.
  쓰기 대기열을 보존해 후속 실행 때문에 대기 중인 작업이 취소되지 않게 한다.
- 중단 전 저장된 보고서는 재사용한다. 체크포인트가 진행되지 않은 보고서도
  내용이 일치하면 원본 재조회 없이 이어서 처리한다.
- 원본 공시 ZIP, 종목·기업·접수번호, 원문 응답과 날짜 목록은 공개하지 않는다.
  실행 요약에는 처리 후보 수·공식 조회 시도 수·완료 월 구간 수만 남긴다.

이 단계는 해당 접수번호가 공식 합병·분할·무상증자 JSON 항목과 일치하는지
확인한다. 신고서에 적힌 예정일과 실제 기업행위 완료일은 구분하며,
수정주가·과거 종목 구성·실제 효력일의 독립 검증과 투자성과 검증은 별도다.
대조 결과의 수집만으로 종목 점수나 투자 인증을 변경하지 않는다.

## 추가 공시 분류의 별도 연속 처리

유상증자·유무상증자·감자·분할합병·주식교환은 별도 보조 원장에 저장한다.
제목 힌트는 조회 경로 선택에만 쓰며, 접수번호가 일치해야 공시 종류 일치로 센다.
지원되는 공식 조회 항목이 없는 주식분할·주식배당 등은 확인 불가로 남긴다.

- 기존 하루 한 묶음(최대 4건) 대조기는 유지하고, 같은 원장에서 연속 재개한다.
- 연속 실행은 최대 128묶음·후보 512건·공식 조회 시도 640회·55분이다.
  어느 한 한도에 도달하면 멈춘다. 매 묶음은 최악의 20회 조회 예산을 확보한다.
- UTC 00:25·04:25·08:25·12:25·16:25·20:25에 하루 6회 실행한다.
  예약분 상한은 후보 3,072건·공식 조회 시도 3,840회이며, 후보당 조회 항목이
  많은 경우 공식 조회 한도 때문에 실제 후보 수는 줄어든다.
- 주요 3종 공시 대조 예약분과 합친 조회 상한은 13,056회/일이다.
  기존 소규모 대조기·기타 수집기·수동/최초 실행 사용량은 별도다.
  공유 키의 제공자 쿼터 오류에서는 중단하며 다른 수집기 여유량을 보장하지 않는다.
- 기존 보조 대조기와 같은 쓰기 대기열에서 순서대로 실행한다.
  검증된 보고서와 조건부 체크포인트를 재사용하고, 실패한 묶음을 통째로 재실행하지 않는다.
  저장소 전송 충돌은 기존 수집기의 제한된 복구 절차만 사용한다.
- `feat(v3.0b): continue supplemental action` main 병합 시 최초 연속 실행을 시작한다.
  시험·PR 작업에는 비밀키를 전달하지 않고 수동 실행은 기본 시험 모드다.

주요 대조기와 보조 대조기의 완료 구간은 서로 독립적이다. 한쪽이 끝나도 전체
기업행위 범위·실제 효력일·수정주가·과거 종목 구성의 검증 완료로 처리하지 않는다.

## 정상 처리 후 즉시 재개와 하루 예산

미완료 작업은 묶음·실행 시간·조회 예산 한도로 정상 종료한 뒤 바로 다음 실행을
예약한다. 네 시간짜리 예약 주기는 API 오류·저장소 장애·하루 예산 소진 뒤의
복구 수단으로 남긴다. 완료·대기·진행 없음·오류 상태에서는 후속 실행을 만들지 않는다.

- 새 실행기들의 하루 예산은 주요 대조 9,216회·보조 대조 3,840회다.
  수동 실행·병합 최초 실행·예약 실행·즉시 후속 실행 모두 같은 예산을 사용한다.
- 조회 전에 비공개 원장에 이번 실행의 최대 호출량을 조건부 저장하고 재확인한다.
  정상 종료 시 실제 시도 수만 차감하고 나머지는 반환한다.
  실행 실패·강제 종료·정산 실패에서는 예약량 전부를 차감한 상태로 남긴다.
- 원장은 종류별·UTC 날짜별로 구분한다. UTC 날짜 전환은 한국 오전 9시이며,
  이 운영 예산 기준이 제공자의 실제 쿼터 초기화 시각을 인증한다는 뜻은 아니다.
  조회는 해당 UTC 날짜가 끝나기 전 멈추도록 실행 시간을 제한한다.
- 이번 기능 배포 전에 이미 실행 중이던 구버전 작업, 기존 소규모 대조기,
  EPS·재무 등 다른 수집기의 사용량은 이 원장에 포함되지 않는다.
  공유 키의 실제 제공자 쿼터 오류에서는 여전히 중단한다.
- 다른 실행이 바꾼 원장은 덮어쓰지 않는다. 동일한 예약/정산 쓰기의 성공 응답만
  유실된 경우에는 저장된 동일 바이트를 확인해 중복 차감 없이 복구한다.

자동 재개는 공시 대조 작업을 끝까지 이어가기 위한 기능이다. 실제 효력일·수정주가·
과거 종목 구성 및 손절·성과 검증을 대조 완료로 대신하지 않는다.

## 저장된 예정일과 KRX 급변 구간의 자동 대조

주요·보조 대조가 모두 끝난 월 구간부터 기존 날짜 대조기를 자동 실행한다.
공시 원문이나 제공자 API는 추가 조회하지 않고, 비공개 보고서와 큐를 읽는다.
한 번에 최대 32묶음·묶음당 8개 접수번호·20분이며, 준비된 구간이 더 있으면
바로 재개한다. 두 원천 대조기의 정상 종료와 예약 실행도 대조를 재개한다.

- 구간 안에 필요한 보고서가 모두 있어야 진행한다. 아직 수집 중인 구간은
  기다리고, 완료됐다고 표시된 구간에서 보고서가 없으면 오류로 중단한다.
- 각 비공개 결과에는 실제 읽은 큐·보고서의 해시와 직전 체크포인트 해시를
  남긴다. 결과 저장·재확인 후 조건부로 체크포인트를 이동한다.
  결과만 저장된 뒤 중단돼도 동일 보고서를 재사용해 중복 집계하지 않는다.
- 같은 접수번호가 인접 월 구간 양쪽에 나타날 수 있으므로 누계는 전역 고유
  접수번호 수가 아니라 '월 구간별 접수번호 관측 수'로 표시한다.
- 예정일과 급변 구간이 가까운지·떨어져 있는지 집계하되, 어느 쪽도 실제
  기업행위 완료·실제 효력일·수정주가·과거 종목 구성의 증거로 승격하지 않는다.
- 종목·접수번호별 근거 경로는 비공개 결과에만 저장한다. 공개 로그에는
  처리 구간·건수·날짜 항목 수와 0회 추가 제공자 조회만 표시한다.

완료된 예정일 대조는 독립적인 실제 효력일 확인을 위한 검토 자료다.
이를 최종 검증 완료나 점수 인증으로 표시하지 않는다.
