# V3.0b 실제 거래대금 10년 수집 경로 (2026-11-03)

## 확정된 사실과 제한

- 기존 KRX 490/490 **파생 코호트**에는 거래 주식수 기반 팩터만 존재한다. 이를 실제 거래대금으로 소급 변환하지 않는다.
- KRX 주식 일별매매정보의 `ACC_TRDVAL`을 출처로 사용한다. `TDD_CLSPRC × ACC_TRDVOL`은 거래대금으로 인정하지 않는다.
- 새 경로는 동일한 2016-10-17~2026-10-16 날짜 후보 490개 5거래일 코호트를 **별도 체크포인트**에서 다시 읽는다. 이전 가격/실적 이력 및 기존 490/490 완료 기록을 덮어쓰지 않는다.
- 최근 거래일에 가까운 5일 코호트부터 과거로 역순 수집하여 20/60/120/240일용 최근 연구 데이터 확보를 앞당긴다.
- 각 5일 코호트마다 KOSPI/KOSDAQ 합계 10회 API를 읽되 응답 원본·일별 가격·일별 거래대금은 영구 저장하지 않는다.
- 암호화폐·NXT·시간외 자료 혼합을 허용하지 않으나, 이 KRX 일별 API가 **09:00~15:30 정규장 전용**인지 독립 검증 전에는 `regular_session_only_verified=false`를 유지한다.
- 이전에 승인된 개인용 비공개 파생지표 연구 저장소 `ykvic1/korean-stock-private-data`에만 수집한다. 원천 소스 공개 저장소/로그/아티팩트 업로드 금지. 추가 데이터 라이선스 적용 여부는 계속 확인한다.

## 기간 축을 충족하기 위한 순서

| 단계 | 자료·검증 | 현재 상태 |
| --- | --- | --- |
| A | `ACC_TRDVAL` 기반 5거래일 합계·후반/전반 비교·서명 금액 흐름 | 실제 API 수집 및 비공개 체크포인트 검증 성공. 최신 현황은 집계 파일 참조 |
| B | 실거래일 20/60/120/240일 연속 코호트 집계와 결측 격리 | 비공개 연구 집계기 및 결측 차단 테스트 완료. 코호트 확보 상황에 따라 분석 가능, 점수 인증 전 |
| C | 정확한 달력 5/10/20/60/120주 및 금액형 OBV | 5일 코호트 ≠ 달력 주봉, 별도 주간 정합성 필요 |
| D | 장기 유입 지속성과 조정 중 거래대금 수축, 가격 괴리 | 통계적 검증 후 배점 결정 |
| E | 시총·유동성 구간별 손절 선도달/MAE/MFE 성과 검증 | 적정 가점·감점 사후 교정 필요 |
| F | 기존 거래량·OBV 20점 교체와 PER/EPS 성장·내재가치 통합 검증 | 현재 **미완료** |

5일 집계 기록에는 직접 보고된 거래대금 총합의 10만원 단위 집계, 5일 중 4개 가격변화 구간의 매수/매도 방향에 따른 거래대금 압력, 초반 2일 대비 후반 2일의 증가 강도 및 결측 표지만 저장한다. 5일 코호트 간 첫날의 주가 방향, 정확한 주봉 종가, 상장폐지·합병/분할 정합성은 아직 증명되지 않았다.

따라서 `investment_scoring_allowed=false`를 유지하고 **실전 최종점수·기존 종목순위에 아직 섞지 않는다.** 새 자료가 중단되거나 검증 실패하면 해당 구간만 보류하고 이전의 원점수·순위·기준일을 보존한다.

## 운영

- 새 전용 체크포인트 `derived/money-historical-checkpoint.json`을 **비공개 저장소**에서 독립적으로 관리한다.
- 작업 한 번 최대 16코호트 / 160 KRX 시장별 조회, 각 파일 저장과 검증 직후 체크포인트를 진행한다.
- UTC 짝수시 49분마다 하루 최대 12회 수집한다(상한 1,920 KRX API 요청/일). 기존 KRX 개인용 API 일 10,000회 상한과 다른 프로젝트 작업의 여유를 고려해 묶음 크기는 늘리지 않는다. 작업이 지연돼도 `concurrency` 잠금으로 원장 충돌을 막는다.
- 코호트 490개를 16개씩 소화하면 추가 실패가 없다는 조건하에 31회 실행이 필요하다. 수집 실패/데이터 부정합은 해당 구간부터 중단하며 과거 점수를 임의 제거하지 않는다.
- [공개 진행률 집계](v3-krx-money-derived-progress.json)는 비공개 체크포인트와 마지막 파일 SHA가 일치할 때만 갱신한다. 개별 종목의 금액·가격·영업정보는 게시하지 않는다.
- 현재 10년 연구 원장의 최종 시점은 2026-10-16이다. 그 이후 정규장 자료는 별도 증분 수집 경로가 필요하며, 소급 기간 확장으로 기존 역순 체크포인트를 재해석하지 않는다.
- 주어진 경로의 기존 파일이 존재하면 검증·채택만 하여 API를 재호출하지 않는다.
- 회귀 테스트가 새 코드에 대한 위양성 또는 장기간 이력 누락을 보이면 수집을 중단하고 기존 점수는 그대로 둔다.

### 2026-11-04 남은 과거 구간 연속 수집

- 정규 실행은 종전대로 **1회 최대 16코호트/160회 API 호출**이다. 기존 예약 수집의 빈도나 소스 선택은 바꾸지 않는다.
- 수동 `max_segments=14` 또는 이름이 `feat(v3.0b): money history fast lane`으로 시작하는 **1회의 병합 커밋**은 최대 14개 세그먼트를 연속 실행한다. 총 상한은 224코호트/2,240회 API 호출이며, 기존 10,000회/일 제한보다 여유를 둔다. 다른 예약 작업까지 합산한 실제 쿼터가 소진되면 제공자의 오류에서 즉시 중단해야 한다.
- 매 세그먼트는 기존 수집기의 16코호트 상한과 코호트별 비공개 SHA/체크포인트 검증을 그대로 사용한다. 일부 세그먼트에서 실패해도 이전에 검증해 저장된 구간을 폐기하지 않는다.
- `historical_cohorts_remaining=0`이면 즉시 중단하며, 100분 경과 후에는 다음 세그먼트를 시작하지 않는다. GitHub Actions 하드 제한은 120분으로 유지한다.
- 이 **연속 수집은 가격·거래대금 정규장 독립 검증이나 달력 주봉 인증을 대체하지 않는다.** 490/490이 되어도 투자점수의 거래주식수 6점 항목을 실제 거래대금 점수로 자동 교체하지 않는다. 이후 20/60/120/240일 및 5/10/20/60/120주 가용성과 장기 지속성·매물소화 성과 검증이 완료된 종목부터 별도 승격한다.
- 퍼블릭 화면에는 합산 실제 거래대금의 추정치 또는 `확정 OBV`로 표시하지 않는다. 원자료·거래일·정규장 검증 후 공개할 수 있는 비재구성형 지표만 따로 승인한다.

### 2026-11-05 정확한 주간 집계 보완

`v3_krx_calendar_week_money.py`는 5거래일 묶음을 주봉으로 부르지 않고, 실제 월~일 달력 주의 XKRX 후보 거래일을 KRX 직접 보고 거래대금으로 조회한다. 휴장으로 1~4거래일만 있는 주도 실제 관측 수를 보존한다. 120주와 직전 동일 기간을 비교할 수 있도록 처음 240주를 고정 기준점에서 최신순으로 쌓고, 이후 새로 완성된 주는 별도로 덧붙인다. 금요일 장마감 이후와 주말에는 해당 주를 완성 주로 취급하며 월~목의 열린 주는 제외한다.

주간 거래대금의 10만원 단위 집계와 관측 수만 기존 비공개 저장소에 보관한다. 원본 응답·일별 거래대금·가격은 저장하지 않는다. 각 주별 불변 파일과 SHA/CAS 체크포인트를 검증하며, 중단 뒤에는 저장된 주를 공급자 재조회 없이 채택한다. 전체 실행은 재시도를 포함해 최대 3,000회 KRX 요청으로 제한하고 기존 과거·증분 수집과 같은 쓰기 대기열을 사용한다. 정규장 전용 여부·기업행위·과거 종목 구성·투자성과의 독립 인증을 주장하지 않는다.
