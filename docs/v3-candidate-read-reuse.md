## 변경

`v3_dart_candidate_catchup.py`가 기존 세 후보 대조기를 한 프로세스에서 순서대로 호출한다.
기존 월별·인접월·제목 후보 검증/원본 효력 제한/독립 체크포인트는 그대로 유지한다.
각 단계는 기존과 같이 최대 네 구간이며, 대기 상태가 나오면 같은 상태를 즉시 재조회하지 않는다.
원본 전체 위험 체인 사전 검증도 같은 저장 객체를 사용한다.

재사용 대상은 엄격한 경로 패턴에 해당하는 접수목록 페이지, KRX 위험 기준 파일과 불변 증분 파일뿐이다.
최초 읽기에서 Git blob SHA와 실제 바이트 일치를 확인하며, 기존 내용 검증기는 매 거래마다 다시 실행한다.
현재 체크포인트·출력 보고서·저장소 메타데이터·파일 목록은 재사용하지 않고 원격에서 읽는다.
누락된 원본도 저장하지 않으므로 나중에 정상 저장된 페이지를 다시 읽을 수 있다.
64MiB/10,000개 상한을 넘으면 재사용만 생략하고 원래 읽기와 검증을 수행한다.
재사용 바이트는 해당 실행의 메모리에만 존재하며 공개 파일/로그/아티팩트에 기록하지 않는다.
오류나 원본 변경을 이유로 거래 자체를 재실행하지 않는다. CAS와 원본 체크포인트 대조는 유지한다.

자동 진행률 보고는 기존의 보수적인 120개월 완료 검사와 비인증 플래그/페이지수 검사를 통과한
공개 집계가 이미 있으면 이를 유지한다. 이때 `private_source_revalidated=false`와 API 호출 0을
명시하며 새 검증 결과로 표시하지 않는다. 수동 write/verify와 불완전한 집계는 원래의 실시간
원본 검증 경로를 유지한다. 신규 폐쇄월 수집/전체 원본 감사/기업행위 대조는 별개로 계속된다.

## 검증 범위

합성 테스트에서 동일 불변 파일 최초 읽기 이후 12회 요청이 원격 추가 조회 없이 처리됐다.
체크포인트/출력은 매번 읽고, 누락·내용 불일치·메모리 상한·대기·거래 실패·마감시간을 검증한다.
이는 실제 운영 속도 개선률이나 API 소모 감소율의 측정값은 아니다. 실제 값은 실행 로그의
`immutable_input_reads_reused`로 확인한다. 기업행위 효력·수정주가·성과 인증을 승격하지 않는다.
